# Proposal

## Why

README 的路線圖列了「Natural-language queries over tracking results (RAG agent)」，但還沒有任何設計。追蹤結果是 MOTChallenge 格式的 `result.txt`（每列：影格、身分、框、信心），問題的答案（幾個不同的人、某個身分出現在哪幾張、某張影格有幾個人）都能由程式精確算出。所以 agent 的做法是「模型把自然語言翻成工具呼叫，數字由程式算」，不是向量檢索；風險全在模型能不能穩定地選對工具、填對參數、對資料裡沒有的東西誠實拒答。

使用者決定只用本機模型，不接雲端。這台機器是一張 32 GB 的 RTX 5090，目前沒有任何 LLM 執行環境，worker 也要用同一張 GPU。在寫 agent 之前，要先用可重跑、可驗證的方式選定模型，並如實記錄選型的證據，而不是憑印象挑。

## What Changes

- 新增 `llm_eval/` 套件與可重跑的命令列，用固定題目比較候選本機模型：
  - 最小的固定工具定義（5 個：不同身分數、某身分的出現時段、單張影格人數、某身分的停留影格數、明確座標區域內的身分）；
  - **獨立撰寫、不與工具共用程式碼**的標準答案程式，直接逐行讀 `result.txt`，另外手算 3 題驗證它本身；
  - 約 30 題：以 MOT17-09-FRCNN 的真實 Result 為主，加一個小型合成序列測邊界（空結果、單人、身分中斷後重現、同一影格大量人）；其中一部分是「資料裡沒有」的問題，必須具體拒答；
  - 四項指標：工具呼叫格式正確率、答案正確率、拒答正確率、延遲中位數；溫度 0、每題 3 次、不算單一總分。
- **先定門檻**：答案正確率 ≥ 90%、拒答正確率 ≥ 90%、工具呼叫格式正確率 ≥ 95%；全部候選都不達標時如實回報，**不降低門檻**，由使用者決定。
- 在專屬名稱（`openmot-llm-eval*`）的 Docker 容器中跑 Ollama，模型放專屬的具名卷；先實測 worker 在 FP16 的顯存，模型載入後約 16 GB 內才算可與 worker 共存。
- 候選模型由我查證（支援工具呼叫、本機可跑、授權清楚）後列出，**使用者確認名單後才拉取**，並先告知下載總量。
- 產出 `docs/llm-selection.md`（選型報告：來源、授權、摘要、大小、載入後顯存、四項指標、每次原始結果、失敗案例、延遲、結論與限制）與原始結果檔。
- 結束後移除專屬容器、卷與拉取的模型，只保留記錄；要保留選定的模型會先問使用者。前後比對 `docker ps -a`、`docker volume ls`、`docker images`。
- 約定：
  - 「不同身分數」預設回原始數，過濾門檻只在題目明確給定時才使用，答案註明定義；
  - 區域只接受明確座標，以框底邊中心點判斷；
  - 五類問題一律具體拒答：影像內容、需要結果檔沒有的序列資訊（影像尺寸的相對區域、幀率的秒數）、跨序列、預測、對應真實人物。

**不在範圍**：agent 迴圈、對外命令列、api 端點、Claude 等雲端模型、向量資料庫；不修改 api、worker、映像與既有相依。這些屬於後續另開的 `add-tracking-query-agent`。

## Capabilities

### New Capabilities

- `llm-selection`: 為追蹤結果提問 agent 選定本機模型的可重跑評估：固定工具與獨立的標準答案、題目組成、評分與門檻、GPU 共存條件、候選確認、資源隔離與清理、選型報告。

### Modified Capabilities

（無。不改任何既有 capability 的需求。）

## Impact

- 新增：`llm_eval/`（工具定義、標準答案、題目產生、Ollama 用戶端、評分、命令列）、`tests/test_llm_eval_*.py`、`docs/llm-selection.md`、原始結果檔；`.gitignore` 增加評估的暫存輸出路徑。
- 不變：`app/`、`worker/`、`jobs/`、映像、`pyproject.toml` 的相依（Ollama 用戶端只用標準函式庫）。
- 資源：專屬的 `openmot-llm-eval*` 容器與卷、一個 Ollama 映像、數個模型（下載量以數十 GB 計，確認名單後才會知道確切數字）。
- 風險與限制：
  - 驗證只涵蓋被選入名單的候選，不代表其他模型；
  - 題目只有 MOT17-09 一個真實序列與一個合成序列；
  - 工具呼叫的最終答案用結構化輸出約束，可能掩蓋模型在自由文字下的行為，報告會寫明；
  - 候選名單與 Ollama 映像版本要等實作時查證，現在不憑記憶決定。
